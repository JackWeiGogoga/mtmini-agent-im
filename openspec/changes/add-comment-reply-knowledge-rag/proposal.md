## Why

当前美团评价自动回复只使用固定文案“很好”，无法根据评价星级、商户经营知识和用户反馈内容生成有针对性的回复。需要引入评论知识库与 RAG 回复生成能力，让系统在无商户知识时可使用官方话术兜底，在商户维护自有知识后可生成更贴合门店场景的回复。

## What Changes

- 新增官方评论回复知识库，按评论类型维护官方回复文案，并在商户无自有知识或智能生成失败时用于随机兜底回复。
- 新增商户自有知识库，支持手工录入 QA 和上传文档两种来源。
- 手工 QA 支持标题、评论类型、问题、回答，限制每个商户最多 500 条，并支持编辑、删除和启停。
- 文档上传支持 `txt`、`docx`、`xlsx`，限制每个商户最多 10 个文档、单文档最大 20M，并通过异步任务解析、清洗、切片和向量化。
- 评论类型统一按 `mt_comment.food_comment_score` 判断：0-2 为差评，3 为中评，4-5 为好评。
- `food_comment_score` 为空或异常时暂不自动回复，记录异常日志并避免进入智能生成链路。
- 新增 RAG 回复生成链路：商户有可用自有知识时，基于当前门店知识检索 topK 片段并调用大模型生成回复。
- RAG 回复需要计费，执行前要求门店算力余额大于 100000；门店授权成功后幂等赠送 800000 算力。
- 首期向量检索不引入 Redis Stack、Qdrant、Milvus 或 SQLite 扩展，使用 MySQL 保存 chunk 和 embedding，由 Java 计算 cosine similarity。
- 修改现有评价自动回复执行链路，将固定文案替换为“官方随机 / 商户 RAG / 官方兜底”的回复内容生成策略。
- 增加知识命中、回复来源、失败原因等可观测信息，便于排查自动回复结果。

## Capabilities

### New Capabilities

- `comment-reply-knowledge`: 管理官方评论回复知识、商户手工 QA、商户上传文档、文档解析切片、知识检索和评论回复内容生成。

### Modified Capabilities

- 无。

## Impact

- 后端数据库：新增评论知识库、文档、切片、解析状态、回复生成记录相关表或字段，并同步更新 `backend/src/main/resources/db/` 下 schema/migration。
- 后端服务：影响 `MtCommentAutoReplyService`、`MtComment` / `MtCommentMapper`、异步任务、OpenAI 兼容调用、文件上传与 COS/本地存储相关服务。
- 算力服务：影响授权成功后的算力赠送、RAG 回复前余额校验和智能回复模型调用消费记录。
- H5：新增商户知识库管理页面与接口，包括手工 QA、文档上传、解析状态和解析片段查看/调整。
- 管理后台：新增官方回复文案维护页面与接口。
- 权限与隔离：商户知识库必须按 `shop_id` 隔离；官方知识库仅后台管理角色可维护。
- 配置与依赖：需要配置 embedding 模型、chat 模型 `deepseek-v4-flash`、chunk 限额、候选召回数量、文档上传格式和大小限制；可能新增文档解析依赖。
- 测试：需要覆盖评论类型判定、官方随机兜底、手工 QA 限额、文档限额、文档解析、向量检索排序、RAG 失败回退和跨店隔离。
