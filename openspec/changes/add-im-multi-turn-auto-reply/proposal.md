## Why

系统已经能够可靠接收并持久化美团 `/imMsg` 两方会话消息，但尚未生成、计费或发送自动回复，也没有可供商家和管理员查看的回复日志与会话历史。现在需要在不拖慢回调、不破坏门店隔离的前提下，建立支持多轮短期记忆、门店知识库 RAG、可靠发送和跨 Session 历史查看的完整 IM 自动回复闭环。

## What Changes

- 对满足条件的用户文本消息，在 `/imMsg` 消息与会话事实可靠入库的同一数据库事务中创建幂等的 `IM_AUTO_REPLY` 异步任务，HTTP 回调线程仍不调用模型、不扣算力、不发送消息。
- 建立门店与顾客的长期 Conversation、30 分钟空闲切分的短期 Session 和统一消息时间线；AI 仅使用当前 Session 最近 100 轮，管理界面可跨 Session 游标加载全部历史。
- 新增 OpenAI-compatible Chat 自动回复服务，复用集群模型限流、任务削峰、系统提示词、敏感词检测和实际 token 算力计费。
- 门店存在可用知识切片时，使用当前问题与近期用户轮次执行 Embedding 和门店级向量召回，将命中片段作为简单 RAG 上下文；检索基础设施失败时重试而不静默降级。
- 新增自动回复执行记录与状态机，持久化稳定的出站 `msg_id`、生成/改写/RAG/token/算力/发送状态；同一回复重试复用已生成正文、消费请求号和出站消息 ID。
- 用户连续消息默认防抖合并；较旧任务、新人工商家回复或动态开关/授权/权益条件变化时安全跳过，避免重复或抢话。
- 管理后台总控台增加按门店查看的回复日志抽屉；H5 增加“日志”Tab，均展示用户消息与 AI 自动回复并严格限制门店可见范围。
- 管理后台新增管理员专用“自动回复记录”页面，包含“消息列表”和“会话列表”两个 Tab；支持以门店信息为核心的搜索、会话聚合、消息数统计、最新消息倒序以及抽屉内跨 Session 向上滚动加载历史。
- 更新数据库初始化结构、菜单权限、三端类型和接口文档，并同步更新 `docs/美团接口调用索引.md`。
- 新增全局美团 API dry-run 安全闸门，覆盖 SDK OAuth、Token 刷新、读写查询与 IM 发送等全部出站调用；默认开启，异步任务无损重排且不伪造远端成功。
- 提供可重复执行的本地 IM 测试数据脚本，预置 `TEST_EPOI_REPLY_001` 门店、短期/历史 Session、用户与 AI 消息、自动回复记录、权益、算力和知识库数据，支持通过 `?wmPoiId=TEST_EPOI_REPLY_001&platform=local-test` 模拟门店登录。

## Capabilities

### New Capabilities

- `im-auto-reply-orchestration`: 定义入站候选判定、异步生成、短期上下文、RAG、敏感词、算力、连续消息合并、发送状态机与重试语义。
- `im-conversation-history`: 定义 Conversation、Session、统一消息时间线、100 轮短期记忆和跨 Session 游标历史查询。
- `im-reply-log-management`: 定义总控台、H5 和管理员全局回复日志及会话列表的查询、搜索、权限和交互要求。
- `meituan-api-dry-run`: 定义所有美团 SDK 出站调用的默认阻断、显式放行、异步任务无损重排和安全日志语义。

### Modified Capabilities

- `im-message-ingestion`: 合法候选消息入库后须在同一事务中创建会话事实、回复记录和异步任务，但回调线程继续禁止模型、算力和发送副作用。
- `im-message-sending`: 自动回复编排须使用稳定唯一的出站消息 ID、持久化发送状态并在任务重试时复用同一消息内容和 ID。
- `merchant-knowledge-base`: 门店存在可用知识时须参与 IM 自动回复的门店隔离向量召回，并把命中片段作为 RAG 上下文。

## Impact

- 后端：IM 入库、统一消息与会话模型、异步任务类型/worker、Chat/Embedding 出口、系统提示词、敏感词、算力、发送客户端编排、H5/管理后台查询接口。
- 数据库：扩展 `mt_im_message`，新增 `mt_im_conversation`、`mt_im_conversation_session`、`mt_im_auto_reply` 及相应唯一键、时间线和门店搜索索引。
- 管理后台：总控台回复日志抽屉、新的自动回复记录页面、路由、菜单、权限、服务与类型。
- H5：新的日志页面、底部 Tab、门店级分页接口与会话历史交互。
- 运维：新增 Chat 模型、自动回复任务、全局美团 API dry-run 与本地测试数据配置；默认不产生任何真实美团出站调用，联调或上线须显式关闭 dry-run；不新增美团接口类型，但正式接入现有两方会话发送接口。
