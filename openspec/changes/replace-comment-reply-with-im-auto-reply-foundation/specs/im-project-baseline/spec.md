## ADDED Requirements

### Requirement: 全新数据库不得包含评价业务结构
系统 MUST 使用面向 IM 消息自动回复的新数据库基线，且 `full_schema.sql` 不得创建评价、评价回复、评价图片分析、差评申诉、评价匿名群聊或评价设置相关表、索引与初始化数据。

#### Scenario: 初始化全新数据库
- **WHEN** 运维在空数据库执行项目的完整 schema
- **THEN** 数据库不存在 `mt_comment` 及任何评价业务派生表
- **AND** 数据库包含门店、授权、权益、算力、支付、异步任务、通用知识库和 IM 业务所需表

#### Scenario: 不提供旧评论数据库迁移
- **WHEN** 实现人员准备数据库脚本
- **THEN** 系统不包含从旧评论表复制、备份、归档或兼容读取数据的迁移逻辑

### Requirement: 评价业务链路必须完整移除
系统 MUST 删除评价查询、授权后评价回补、评价定时拉取、评价自动回复、评论日志分析、评价图片识别、差评申诉和评价匿名群聊跟进的运行时代码与配置。

#### Scenario: 应用启动并运行定时任务
- **WHEN** 新版本应用启动且异步 worker 与调度器运行
- **THEN** 系统不注册评价拉取定时任务
- **AND** 系统不轮询或执行 `AUTH_COMMENT_BACKFILL`、`COMMENT_AUTO_REPLY`、`COMMENT_LOG_ANALYSIS`、`COMMENT_AUTO_COMPLAINT` 或 `COMMENT_AUTO_IM_FOLLOW_UP`

#### Scenario: 检查美团外部调用
- **WHEN** 新版本完成授权和日常运行
- **THEN** 系统不调用评价查询、添加商家评价回复、评价申诉、评价建群或评价匿名群聊发送接口

### Requirement: 通用基础能力必须保留
系统 SHALL 保留门店授权、access token、关闭订单推送、门店权益、订阅订单、算力账户、充值支付、数据库异步任务、LLM 基础设施、系统提示词、对象存储、Embedding、向量检索和管理后台基础权限能力。

#### Scenario: 评论代码删除后验证基础能力
- **WHEN** 评价业务代码和表被移除
- **THEN** 后端能够完成编译和启动
- **AND** 授权、权益、算力充值与查询、支付回调、知识库和通用异步任务仍可使用

### Requirement: 三端界面必须去评价化
H5 和管理后台 MUST 删除评价统计、评价回复日志、评价处理日志、官方评价回复文案和差评处理开关，并将剩余服务状态统一描述为 IM 消息自动回复。

#### Scenario: 商家访问 H5
- **WHEN** 商家进入 H5 首页
- **THEN** 页面展示 IM 消息自动回复、授权、权益、算力、知识库和客服相关信息
- **AND** 页面不展示评价数量、好评差评、评价日志或差评处理开关

#### Scenario: 管理员访问管理后台
- **WHEN** 管理员查看总控台和菜单
- **THEN** 后台不提供评价处理日志和官方评价回复文案入口
- **AND** 总控台只保留门店、授权、权益、算力和 IM 自动回复主开关等仍有效信息

### Requirement: 当前阶段不得触发 IM 自动回复发送
本变更 SHALL 只建立授权配置、开关和消息入库基础，不得因收到消息而调用模型、扣除消息回复算力或发送 IM 回复。

#### Scenario: 收到可回复的用户文本消息
- **WHEN** 系统持久化 `biz_type=1`、`msg_source=2`、`msg_type=1`、`has_reply=1` 的消息
- **THEN** 系统只保存消息并返回回调结果
- **AND** 系统不创建生成任务、不扣算力且不调用发送消息接口

### Requirement: 项目文档必须反映 IM 业务基线
系统 MUST 更新仓库说明和美团接口索引，移除评价业务描述并登记实际保留和新增的美团调用。

#### Scenario: 开发者阅读项目文档
- **WHEN** 开发者查看根目录及各端 `AGENTS.md` 和 `docs/美团接口调用索引.md`
- **THEN** 文档将项目描述为 IM 消息自动回复应用
- **AND** 接口索引不再列出评价业务调用，并包含两个授权后 IM 设置接口与 `/imMsg` 入站回调
