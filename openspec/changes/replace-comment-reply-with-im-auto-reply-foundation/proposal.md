## Why

当前仓库由评价自动回复项目复制而来，仍包含评价查询、评价回复、差评申诉、评价匿名群聊等完整旧业务，已经与新的 IM 两方会话自动回复方向冲突。项目将使用全新数据库，需要直接建立不含评价业务的新基线，并先完成门店授权后的 IM 初始化、消息可靠入库和可复用基础能力去评价化，为后续消息自动回复提供稳定入口。

## What Changes

- **BREAKING** 删除评价查询、授权回补、定时拉取、评价自动回复、评论日志分析、差评申诉、评价匿名群聊跟进及其后端代码、任务类型、配置、提示词、测试和文档。
- **BREAKING** 从全新数据库结构中移除全部评价业务表、评价开关字段、评价菜单权限和初始化数据；不提供旧评价数据迁移、兼容或备份方案。
- 保留门店授权、access token、订单推送控制、门店权益、算力账户与支付、数据库异步任务、LLM 基础设施、系统提示词、COS、Embedding、向量检索和商家知识库等基础能力。
- 将商家知识库从评价回复语义中拆出，保留门店 QA、文档、切片和既有向量能力，删除官方评价回复模板、评价情感分类及评价回复/申诉测试入口。
- 新增门店 IM 自动回复设置及历史记录，仅保留一个本地 `auto_reply_enabled` 主开关；删除差评处理/申诉开关，并同步调整 H5、管理后台和埋点语义。
- 门店授权核心状态保存成功后，异步调用美团“设置门店 IM 状态”接口，以 `imStatus=1` 开启 IM；随后调用“设置门店智能回复机器人开关状态”接口，以 `type=0`、`switchStatus=0` 关闭全部机器人开关；成功后开启本地 IM 自动回复主开关。
- 授权后 IM 初始化只调用上述两个设置接口并记录结果，不调用付费的机器人开关查询接口复核；初始化失败不回滚已经成功的授权，按幂等异步任务策略重试。
- 改造 `POST /api/callbacks/meituan/imMsg`，按美团统一消息回调规范验签，兼容 `push_content` 为 JSON 对象或 JSON 字符串，接收并持久化所有两方会话消息类型和双方消息。
- 明确两方会话接收类型为 `1` 文本、`2` 图片、`3` 其他、`17` 卡片；视频不是官方独立类型，若作为“其他”到达则只原样入库，不做媒体识别或下载。
- 新增可供后续回复流程复用的两方会话发送客户端，固定 `biz_type=1`、`msg_source=1`，使用通用 IM 密钥加密正文，并支持官方发送接口列出的文本、图片和其他类型；客户端不自动重试，也不由回调直接触发。
- 将旧评价回复敏感词能力去评价化后保留：沿用既有分类词库、归一化检测、严重级别和知识内容拦截，并在两方会话文本发送前强制检测；命中时不得调用美团发送接口，后续 IM 回复生成流程可基于安全命中结果执行改写或兜底。
- 新增通用 IM 消息表，保存回调公共字段、消息业务字段、原始密文、解析/解密状态和安全原始载荷；使用外层回调消息 ID 与内层平台消息 ID 双重幂等，并按门店与用户建立会话查询索引。
- 回调在消息持久化成功或确认重复后返回成功；瞬时入库失败返回失败以触发平台重试，已落库但暂时无法匹配门店或解密失败的消息保留失败状态供后续补处理。
- 更新 H5 和管理后台，删除评价统计、评价日志、差评开关及评论专属页面，仅保留 IM 自动回复服务状态、授权、权益、算力、知识库和其他基础功能。
- 本变更只建设 IM 自动回复基础及可复用发送客户端，不包含消息内容生成、算力扣减、自动发送编排、回复状态机、回复重试或消息日志页面；这些能力在后续变更中定义。

## Capabilities

### New Capabilities

- `im-project-baseline`: 定义全新数据库和应用中移除评价业务、保留通用基础能力以及前后端去评价化后的项目基线。
- `merchant-knowledge-base`: 定义脱离评价语义后的门店 QA、知识文档、切片、Embedding 和向量检索能力。
- `im-auto-reply-settings`: 定义门店 IM 自动回复主开关、设置历史、授权默认开启和算力不足关停等本地控制语义。
- `im-authorization-setup`: 定义授权后开启门店 IM、关闭美团智能回复机器人以及异步幂等、重试和可观测性要求。
- `im-message-ingestion`: 定义 `/imMsg` 验签、协议兼容、门店映射、全量消息持久化、双重幂等和回调响应语义。
- `im-message-sending`: 定义 `biz_type=1` 两方会话的通用发送客户端、消息类型、敏感词发送前检查、加密、会话字段和安全边界。

### Modified Capabilities

无。现有 OpenSpec 规格已清理，本变更全部以新的能力规格建立项目契约。

## Impact

- 后端：授权后异步任务、任务类型与 worker、IM 客户端、回调 Controller、门店设置、算力不足关停、知识库、首页/总控台统计和大量评价专属实体、Mapper、Service、配置与测试。
- 数据库：重写 `full_schema.sql` 的业务基线，新增 IM 设置、设置历史和消息表，保留基础表与通用知识库表，不创建任何评价业务表。
- H5：重写首页服务语义与开关，删除评价统计、差评开关和评价日志，保留授权、权益、算力、充值、知识库和客服。
- 管理后台：删除评价处理日志和评价回复文案，调整总控台指标与权限，保留并去评价化商家知识库。
- 美团接口：新增两个授权后设置调用、改造 IM 两方会话消息入站处理，并保留 `biz_type=1` 两方会话发送基础；必须同步更新 `docs/美团接口调用索引.md`。
- 部署：项目只面向全新数据库，不承担旧评论数据库升级和数据迁移兼容。
