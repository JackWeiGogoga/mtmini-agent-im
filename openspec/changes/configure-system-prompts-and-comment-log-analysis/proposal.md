## Why

当前评价回复日志里的 AI 分析文案仍是固定占位，无法体现顾客评分、标签、评价内容和配送表现；同时系统内多个大模型 prompt 分散在代码或资源文件中，后续调优需要发版，缺少可审计、可扩展的后台配置能力。

本次变更将评论日志分析从固定文案改为大模型生成并持久化，同时建立统一的系统提示词配置能力，让评价回复、图片识别、日志分析等 prompt 可在管理后台动态维护，并保留资源文件兜底。

## What Changes

- 新增通用系统提示词配置能力，按 `prompt_key` 管理 prompt 内容、启用状态、版本、默认资源文件、变量说明和更新审计信息。
- 管理后台新增“系统提示词”配置页面，支持查看、编辑、启停、恢复默认、预览变量说明，并受权限控制。
- 后端新增系统提示词管理接口和运行时解析服务，业务调用优先读取启用的数据库配置，未配置或停用时回退到资源文件/代码默认值。
- 将 `backend/src/main/resources/prompts/comment_log.prompt` 优化为评论日志分析 prompt，并作为 `COMMENT_LOG_ANALYSIS` 的默认模板。
- 自动回复成功后为当前评价生成 AI 分析日志文案，保存到本地评价数据，并由 H5 日志接口返回真实分析文案。
- 不新增或修改美团外部接口调用，不改变现有美团添加商家回复的幂等边界。

## Capabilities

### New Capabilities

- `system-prompt-configuration`: 管理后台动态配置系统提示词，并为后端大模型调用提供可版本化、可兜底的 prompt 解析能力。
- `comment-log-analysis`: 基于评价全量字段生成、持久化并展示 AI 分析日志文案。

### Modified Capabilities

- `h5-comment-reply-log`: H5 评价回复日志从固定“AI 分析结果”占位改为返回已生成的 AI 分析日志文案，缺失时仍有明确兜底。

## Impact

- 后端：新增 prompt 配置表、实体、Mapper、Service、Controller、参数/VO；改造现有大模型 prompt 构建路径；新增评论日志分析生成与持久化字段；调整 H5 日志接口取值。
- 前端：新增系统提示词配置页面、路由、权限包裹、接口封装和类型定义；新增菜单初始化 SQL。
- 数据库：新增系统提示词配置表和必要索引；`mt_comment` 或独立评论分析表新增分析文案、模型、token、状态、错误、更新时间等可观测字段。
- 运维：默认 prompt 继续随资源文件发布，后台配置覆盖默认值；配置变更需要记录操作者和更新时间，便于回滚。
- 外部系统：不新增美团接口；评论日志分析大模型调用复用现有 OpenAI 兼容配置并扣减算力，优先按 token usage 计费，usage 缺失时使用兜底算力。
