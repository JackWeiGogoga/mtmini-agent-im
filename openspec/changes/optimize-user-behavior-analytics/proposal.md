## Why

现有行为统计仍残留旧推广出价业务的事件和指标，当前 18 个事件中只有少数存在调用，统计页的大部分字段长期为零；同时应用访问、日志查看、知识库使用、有效充值提交等现行业务行为缺少可靠记录。需要在数据量仍较小时统一事件语义，并把开关成功变更等可靠业务事实纳入统计，形成可解释、可追溯的门店行为看板。

## What Changes

- 弃用旧推广开关、策略配置、AI 高峰期、手动出价、首充 GIF 等遗留事件和统计字段，保留必要的历史数据兼容口径。
- 增加应用会话、页面访问、客服入口、外部活动、有效充值提交、兑换码应用结果、日志详情和知识库操作等现行业务事件。
- 为客户端事件增加会话标识和事件唯一标识，支持访问会话分析和重复上报去重。
- 修正算力支付、兑换码和 Tab 点击的事件语义，避免无效点击、展开与收起、重复点击当前页面污染统计。
- 行为统计以可见门店为基础，联合行为事件与开关变更历史，展示零行为门店以及 H5、PC 和系统来源的开关成功变更数。
- 管理后台补充回复日志、知识库入口等按门店的有效行为，并恢复严格的事件类型约束。
- 对事件上下文实施 JSON 对象校验、长度限制和敏感信息约束。

## Capabilities

### New Capabilities

- `user-behavior-analytics`: 规范 H5 与 PC 行为事件采集、事件去重、门店级统计聚合以及业务事实统计口径。

### Modified Capabilities

无。

## Impact

- 后端：行为事件枚举、上报参数与服务、Mapper 聚合、统计 VO、数据库表结构和迁移脚本。
- H5：应用会话和页面访问上报、首页、日志、算力、客服、知识库及底部 Tab 交互。
- 管理后台：总控台行为上报、行为统计类型与表格列。
- 数据：新增 `client_event_id`、`session_id` 字段；旧事件明细保留，但不再由新客户端产生。
- 接口：沿用 `/api/h5/behavior-events` 与 `/api/system/behavior-events`，扩展请求字段并收紧事件上下文格式。
