# 8) 你自己实现 H5 时，建议照着这样做

前端只负责：

- 调 `/api/auth/me`
- 拉当前商家信息、权限、套餐信息
- 后续所有业务请求只认你自己的登录态

# 7) 当前项目采用的实现方案（2026-03-24）

结合新的竞品分析和当前代码实现，项目已改为：

```text
美团跳转 H5 根地址
    ↓
H5 根入口检测 wmPoiId / bizToken / platform / appKey
    ↓
如存在平台启动参数，则自动跳转到 /#/pages/auth/callback/index?...
    ↓
H5 callback 页读取 wmPoiId / bizToken / platform / appKey
    ↓
POST /api/mt/auth/login
    ↓
后端按 wmPoiId = epoiId 查询门店
    ↓
后端创建 Redis 会话型业务 token，并把 epoiId 写入 LoginUser
    ↓
H5 保存 token / shopInfo / version 到 localStorage
    ↓
后续 H5 业务接口统一从 token 对应的 Redis 会话里取 epoiId 恢复当前门店
```

当前边界约束：

- **不再使用** `/auth/redirect`、`/api/mt/auth/exchange`、Redis ticket 中转逻辑
- 后端后续业务**统一使用 session 中的 `epoiId`** 恢复当前门店
- 前端**不暴露内部 `shopId`**
- `poiId` 只作为可选展示字段返回，**不作为鉴权主键**
- 当前项目登录响应使用 `shopInfo`，本地存储键也使用 `shopInfo`，**不沿用竞品的 `userInfo` / `dzhmUserinfo` 命名**
- `bizToken` 当前阶段只透传保留，后续再补平台校验

当前对接地址约定：

- 美团当前建议配置的 H5 地址：`https://aia.waimaidashi.com/`
- 美团只需要向根地址追加 query 参数，例如：

```text
https://aia.waimaidashi.com/?wmPoiId=17740748781&bizToken=mock-biz-token&platform=0
```

- H5 根入口会自动规范化跳转到：

```text
https://aia.waimaidashi.com/#/pages/auth/callback/index?wmPoiId=17740748781&bizToken=mock-biz-token&platform=0
```

- 这样可以避免把 `#` 作为第三方平台对接前提
