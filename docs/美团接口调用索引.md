# 美团接口调用索引

## 范围与成本约束

- `backend/` 是唯一真实调用美团开放平台的模块；`frontend/` 与 `h5/` 只调用本系统接口。
- 授权后的 IM 初始化只调用两个固定写接口，不调用“查询门店 IM 状态”或“查询智能回复机器人开关状态”做前置判断、写后确认或重试确认。
- 机器人开关查询接口是付费接口，项目代码、测试和运维流程均禁止调用。固定写操作由数据库异步任务按既定参数重试。
- `/imMsg` 当前范围仅包含验签、解析、解密和可靠入库，不生成回复、不扣减算力、不创建回复任务，也不从回调中发送消息。
- 后端保留独立的 `biz_type=1` 两方会话发送客户端，供后续回复编排复用；客户端不调用状态查询接口，也不在内部重试。

## 授权后的 IM 初始化

授权核心数据提交后，`MtAuthAsyncTaskService` 以门店和授权事件生成幂等键，入队 `AUTH_CONFIGURE_IM`。worker 每次执行都会重新读取当前门店 token，并严格按以下顺序处理：

1. 开启门店 IM；
2. 关闭美团全部智能回复机器人开关；
3. 将本地 `mt_im_auto_reply_setting.auto_reply_enabled` 开启，并记录 `AUTH` 来源历史。

任一远端写操作失败时，本地开关保持关闭，任务按数据库策略重试；重试只重复固定写操作，不增加查询调用。

### 设置门店 IM 状态

- 文档：<https://developer.meituan.com/docs/api/wmoper-ng-im-setPoiIMStatus>
- SDK request：`SetPoiImStatusRequest`
- 固定参数：`imStatus=1`
- 实现：`backend/src/main/java/com/gogoga/backend/client/MtImConfigurationClient.java`

### 设置门店智能回复机器人开关状态

- 文档：<https://developer.meituan.com/docs/api/wmoper-ng-im-autosend-setAutoSendConfigInfo>
- SDK request：`SetAutoSendConfigInfoRequest`
- 固定参数：`allStatus=[{"type":0,"switchStatus":0}]`
- 语义：`type=0` 操作全部开关，`switchStatus=0` 关闭。

响应日志只保留阶段、返回码、traceId 和是否存在数据，不输出 token、请求秘密或完整上游正文。

## 接收 IM 两方会话消息

- 文档：<https://developer.meituan.com/docs/msg/msg_waimaing_0667a278-09c5-4d5d-98b3-6a92b5d3cfd8>
- 本地入口：`POST /api/callbacks/meituan/imMsg`
- 格式：`application/x-www-form-urlencoded`
- 验证：使用配置的 `mt.sign-key` 对外层全部非空参数验签，并校验 `developerId`、`businessId`；内层 `sig` 只留存，不替代外层验签。
- 解析：兼容 `message.push_content` 为 JSON 对象或转义字符串，原始 JSON 保留未知扩展字段。
- 门店关联：优先使用内层 `app_poi_code` 匹配 `mt_shop.epoi_id`，再回退外层 `ePoiId`。
- 解密：使用 `mt.im.secret`；成功保存密文、明文与 SHA-256，失败保存安全状态和摘要。
- 消息类型：接收协议声明 `msg_type=1` 文本、`2` 图片、`3` 其他、`17` 卡片；当前均可透明入库，未知类型也不在接收侧丢弃。
- 图片/媒体边界：图片内容按协议密文解密后原样保存，当前不做下载、结构化解析或展示处理；官方没有独立的视频类型，若上游把视频类扩展作为 `msg_type=3` 推送，只按“其他”消息透明保存。
- 入库：不按 `msg_source`、`msg_type`、`has_reply` 或零值 `order_id` 过滤；门店未匹配、解析不完整或解密失败也要落库后返回成功。
- 幂等：`callback_msg_id` 唯一，且 `(app_id, platform_msg_id)` 唯一。
- 响应：确认落库或确认重复后返回 `{"code":0,"message":"success"}`；验签/协议失败或数据库结果未知时返回非 0。

普通日志不得输出消息正文、完整 payload、完整密文、token 或 `mt.im.secret`。

## 发送 IM 两方会话消息

- 文档：<https://developer.meituan.com/docs/api/wmoper-ng-im-msg-send>
- SDK request：`SendImMsgWmoperRequest`
- 本地实现：`backend/src/main/java/com/gogoga/backend/client/MtImMessageClient.java`
- 固定上下文：`biz_type=1`、`msg_source=1`（商家）、`has_reply=2`；不再使用评价匿名群聊的 `biz_type=4`、`comment_id`、`group_id`。
- 发送类型：只放行两方会话接口声明的 `msg_type=1` 文本、`2` 图片、`3` 其他；`17` 卡片只在接收协议中声明，发送客户端会拒绝；不存在独立的视频发送类型。
- 敏感词：`msg_type=1` 文本在加密前复用通用 `SensitiveWordService`；命中时返回 `SENSITIVE_WORD_HIT`，安全摘要只包含类别、命中数和最高严重级别，不加密正文且不调用美团。图片和“其他”类型正文按 URL、JSON 或 Base64 等不透明协议载荷处理。
- 加密：调用方传入明文内容，客户端复用 `mt.im.secret` 按 AES/CBC/PKCS5Padding 加密后设置 `msg_content`。
- 会话参数：调用方传入稳定且唯一的 `msg_id`、10 位秒级 `cts`、`order_id`、`open_user_id` 和场景字段；同一业务消息重试时必须复用 `msg_id`。
- 调用边界：客户端每次方法调用只请求一次美团发送接口，不生成消息 ID、不查询机器人或 IM 状态、不做内部重试、不生成回复、不扣算力。
- 当前未把该客户端接入 `/imMsg` 回调；后续自动回复任务需要在可靠入库之外独立编排。

上游响应摘要只保留返回码、traceId 和是否存在数据；本地敏感词失败只保留类别、命中数和最高严重级别。两者均不输出 access token、消息明文、具体命中词、密文或上游完整错误正文。

## 其他保留链路

- 授权后仍通过 `AUTH_BLOCK_ORDER_PUSH` 关闭订单类消息推送；项目不接收或保存外卖订单推送数据。
- `AUTH_BACKFILL_POI_ID` 只读取订单 ID 和详情中的 `poiId`，不保存订单明细。
- 权益同步、订阅订单拉取、token 刷新、H5 直登和美团活动页跳转继续沿用原有门店隔离与幂等约束。
