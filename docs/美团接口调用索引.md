# 美团接口调用索引

## 范围说明

- 统一登记仓库内所有和美团相关的外部调用与关键接入点。
- `backend/` 是生产环境中真正向美团发起外部请求的代码位置。
- `h5/` 和 `frontend/` 不直接请求美团开放平台；它们只调用本系统后端接口。
- 评价自动回复任务依赖有效门店授权 token 和门店权益，候选查询会过滤 `mt_access_token.auth_status = 1`。

## 订单推送关闭

- 自动回复业务不接收美团订单数据，不保留订单回调入口，也不维护 `mt_order` / `mt_order_detail`。
- 门店授权后，`MtAuthAsyncTaskService` 会入队 `AUTH_BLOCK_ORDER_PUSH`，通过“更新开发者绑定门店消息推送屏蔽列表”接口关闭订单类消息推送。
- 本地保留 `MtOrderPushControlService` 和对应手动联调入口，仅用于控制美团订单推送开关状态。

## 授权后补齐门店 poiId

- 授权核心数据提交后，`MtAuthAsyncTaskService` 会入队 `AUTH_BACKFILL_POI_ID`。
- 仅当 `mt_shop.poi_id` 为空时执行：从昨天开始最多回看 4 天，每天查询一条订单；找到订单后查询订单详情并将其中的 `poiId` 回填到对应门店。
- 该链路只读取订单 ID 和详情中的 `poiId`，不接收订单推送，也不保存订单及订单明细。

## 评价自动回复

### 查询门店评价信息

- 文档：`10.6.1 查询门店评价信息`
- 地址：`https://api-open-cater.meituan.com/wmoper/ng/comment/queryCommentList`
- SDK request：`com.meituan.sdk.model.wmoperNg.comment.queryCommentList.QueryCommentListRequest`
- Dry run：`mt.comment.query-dry-run=true` 时不调用美团查询评价接口，只记录日志并跳过本次同步。
- 本地入口：
  - `backend/src/main/java/com/gogoga/backend/task/MtCommentAutoReplyTask.java`
  - `backend/src/main/java/com/gogoga/backend/task/MtAsyncTaskWorkerTask.java`
  - `backend/src/main/java/com/gogoga/backend/service/MtCommentAutoReplyService.java`
- 固定参数：
  - 授权回补：`startTime` 为当天 0 点往前 `mt.comment.lookback-days` 天，默认 7 天；`endTime` 为当天 0 点。
  - 日常定时：`startTime` 为前 1 天 0 点；`endTime` 为当天 0 点。
  - `offset`：分页起点。
  - `limit`：默认 20，最大 20。
  - `replyStatus`：`0`，只查询未回复。
  - `bizKey`：当前实现按 `biz~1002~Waimai~{ePoiId}` 拼接。
- 落库：评价字段保存到 `mt_comment`，`comment_order_detail` 和原始响应以 JSON 保存。
- 幂等：`mt_comment.comment_id` 唯一，用户首次评价和追加评价同 ID 时更新同一条记录。

### 根据评价id添加商家回复

- 文档：`10.6.2 根据评价id添加商家回复`
- 地址：`https://api-open-cater.meituan.com/wmoper/ng/comment/addReply`
- SDK request：`com.meituan.sdk.model.wmoperNg.comment.wmoperCommentAddReply.WmoperCommentAddReplyRequest`
- Dry run：
  - `mt.comment.reply-dry-run=true` 时不调用美团添加商家回复接口。
  - 同步流程不会入队新的 `COMMENT_AUTO_REPLY` 任务。
  - 如果已有回复异步任务被 worker 领取，会按 `mt.comment.dry-run-reschedule-seconds` 无损重排，不标记成功、不消耗重试次数。
- 本地入口：
  - `backend/src/main/java/com/gogoga/backend/task/MtAsyncTaskWorkerTask.java`
  - `backend/src/main/java/com/gogoga/backend/service/MtCommentAutoReplyService.java`
  - `backend/src/main/java/com/gogoga/backend/service/CommentProcessingRetryService.java`（管理员手动重试失败任务）
- 请求参数：
  - `commentId`：查询评价接口返回的评价 ID。
  - `ePoiId`：门店 `mt_shop.epoi_id`。
  - `reply`：由大模型基于评价内容生成；商户知识库只在检索相似度达到阈值时作为 RAG 上下文补充。模型异常时会回退官方回复/默认回复；算力余额为空、低于门槛或实际扣费不足时不再发送兜底回复，而是将当前评价标记为跳过，并以 `SYSTEM / POWER_BALANCE_NOT_ENOUGH` 关闭门店 AI 回复主开关和差评处理/申诉开关。
- 落库：成功后更新 `mt_comment.reply_status=1`、`auto_reply_status=SUCCESS`、`auto_reply_content`、`auto_reply_at`；失败记录 `auto_reply_status=FAILED` 和错误摘要。管理员手动重试会复用原 `comment:{commentId}` 幂等任务键并立即重新入队。

### 美团评价申诉

- 文档：`wmoper-ng-comment-complain-report`
- 文档地址：`https://developer.meituan.com/docs/api/wmoper-ng-comment-complain-report`
- 地址：`https://api-open-cater.meituan.com/wmoper/ng/comment/complain/report`
- SDK request：`com.meituan.sdk.model.wmoperNg.comment.commentComplainReport.CommentComplainReportRequest`
- Dry run：
  - `mt.comment.reply-dry-run=true` 时不调用美团评价申诉接口；申诉内部配置 `mt.comment.complaint-dry-run` 复用同一个环境变量 `MT_COMMENT_REPLY_DRY_RUN`。
  - 差评自动投诉任务会先完成类型判断、文本生成、算力幂等扣减和本地 `GENERATED` 状态记录，再按 `mt.comment.dry-run-reschedule-seconds` 无损重排，不标记真实成功。
- 本地入口：
  - `backend/src/main/java/com/gogoga/backend/task/MtAsyncTaskWorkerTask.java`
  - `backend/src/main/java/com/gogoga/backend/service/MtCommentAutoReplyService.java`
  - `backend/src/main/java/com/gogoga/backend/service/impl/MtCommentComplaintServiceImpl.java`
  - `backend/src/main/java/com/gogoga/backend/service/CommentProcessingRetryService.java`（管理员手动重试失败任务）
- 触发条件：
  - 评价 `valid=1`；`valid=0` 的无效评价仅落库审计，不参与自动回复、差评申诉、IM 跟进、商家端日志或评价统计。
  - 评论敏感类型 `comment_type` 仅处理 `4`、`5`、`10`；其他值仅落库审计。商家端对类型 `5` 屏蔽评价原文，评价统计仅计算类型 `4`、`5`，类型 `10` 不计分。
  - `COMMENT_AUTO_REPLY` 成功后，先忽略 0 分及其他无效值，再取 `product_score`、`packing_score`、`delivery_comment_score` 与 `food_comment_score` 的最低有效分；1-2 分判定为 `BAD`。
  - 当前门店自动回复主开关开启，且差评处理/申诉开关 `negative_comment_appeal_enabled=1`。
  - 当前门店存在有效 access token，且任务 `shopId` 与评价所属 `shop_id` 一致。
- 请求参数：
  - `commentId`：查询评价接口返回的评价 ID，SDK 字段类型为字符串。
  - `reportTypeCode`：大模型基于评价内容、评分、标签、配送时效和图片上下文判断；无效或不可解析时默认 `47` 内容无意义评价。
  - `reportContent`：大模型生成的申诉文本，限制 300 字以内，并经过敏感词检测。
  - `picIds`：当前系统暂不传；如后续美团返回可提交的图片 ID，再从本地评价图片字段映射。
- 落库：
  - `mt_comment_complaint` 保存申诉状态、类型、文本、模型、prompt 版本、token usage、算力、请求/响应、错误和耗时。
  - `mt_comment` 保存当前申诉快照：`complaint_status`、`complaint_report_type_code`、`complaint_report_content`、`complaint_at`、`complaint_error`。
- 幂等：
  - 异步任务 `bizKey` 为 `comment-complaint:{commentId}`。
  - `mt_comment_complaint` 通过 `shop_id + comment_id` 唯一索引防重复。
  - 已成功申诉的评价跳过模型生成、算力扣减和美团接口调用。
  - 算力扣减 requestNo 为 `COMMENT_AUTO_COMPLAINT:{commentId}`，重复任务不会重复扣费。
  - 管理员手动重试失败申诉时复用原异步任务；已有生成内容时从 `GENERATED` 阶段继续，避免重复生成和重复扣费。

### 创建评价联系群

- 文档：`10.4.9 创建群接口`
- 地址：`https://api-open-cater.meituan.com/wmoper/ng/im/createGroup`
- SDK request/response：
  - `com.meituan.sdk.model.wmoperNg.im.createGroup.CreateGroupRequest`
  - `com.meituan.sdk.model.wmoperNg.im.createGroup.CreateGroupResponse`
- 本地入口：
  - `backend/src/main/java/com/gogoga/backend/task/MtAsyncTaskWorkerTask.java`
  - `backend/src/main/java/com/gogoga/backend/service/impl/MtCommentImFollowUpServiceImpl.java`
  - `backend/src/main/java/com/gogoga/backend/client/MtCommentImClient.java`
  - `backend/src/main/java/com/gogoga/backend/service/CommentProcessingRetryService.java`（管理员确认后的失败补偿）
- 固定参数：`groupType=1`，`commentId` 为当前美团评价 ID，使用评价所属门店 access token。
- Dry run：`mt.comment.im-follow-up.create-group-dry-run=true` 时不调用接口、不写 `create_group_attempted_at`、不伪造 `group_id`，任务无损重排；所有 profile 默认开启。
- 落库：`mt_comment_im_follow_up` 保存 `group_id`、`new_group`、`ctime`、`state`、`close_type`、attempt、脱敏响应摘要和耗时；`mt_comment` 保存当前群 ID 与 IM 状态快照。
- 单次真实尝试：调用前原子写入 `create_group_attempted_at`；业务失败、缺少 `group_id`、异常、超时或结果未知均记录终态失败，worker 不自动再次建群。管理员确认失败原因已处理后，可从评价处理日志显式补偿重试；此操作会清除失败阶段的建群 attempt，并可能再次真实调用美团。
- 门店隔离：任务 `shopId`、评价 `shop_id`、门店权益和 access token 必须一致。

### 发送评价匿名群聊消息

- 文档：`发送IM消息（非接单）`
- 文档地址：`https://developer.meituan.com/docs/api/wmoper-ng-im-msg-send`
- 地址：`https://api-open-cater.meituan.com/wmoper/ng/im/msg/send`
- SDK request：
  - `com.meituan.sdk.model.wmoperNg.im.sendImMsgWmoper.SendImMsgWmoperRequest`
  - `com.meituan.sdk.model.wmoperNg.im.sendImMsgWmoper.PushContent`
- 本地入口同“创建评价联系群”。
- 固定参数：`bizType=4`、`msgType=0`、`msgSource=1`、`sceneTag=-1`，并传稳定唯一 long `msgId`、首次准备发送时保存的 10 位 `cts`、`commentId`、`groupId` 和加密 `msgContent`。
- 消息生成与计费：使用后台可配置 `COMMENT_IM_FOLLOW_UP_MESSAGE`；允许“核实后补偿”等明确以核实为前提的条件式售后表述，仍禁止直接或无条件补偿以及红包、优惠券、退款、赔付、补发等具体利益承诺。模型或输出失败时使用 `MT_COMMENT_IM_FALLBACK_MESSAGE` 兜底模板并渲染 `{{commentContent}}`，评价变量按整条消息 150 字上限安全截断，不重试模型。算力 requestNo 为 `COMMENT_IM_FOLLOW_UP:{commentId}`，模型成功按 usage、兜底默认按 1000 算力扣费。
- 加密：开发者配置 `MT_IM_SECRET` 的 UTF-8 字节必须恰好 16 字节，相同字节同时作为 AES key 和 IV，算法 `AES/CBC/PKCS5Padding`，输出标准 Base64。日志、后台响应和数据库请求摘要不保存密钥或完整密文。
- Dry run：`mt.comment.im-follow-up.send-message-dry-run=true` 时不调用接口、不写 `send_attempted_at`、不标记成功；保留真实群和生成消息后无损重排，所有 profile 默认开启。
- 单次真实尝试：调用前原子写入 `send_attempted_at`；失败、异常、超时和结果未知均记录终态，不自动重发。管理员确认后手动补偿时保留原 `group_id` 与 `msg_id/cts`，清除发送 attempt 后再次调用，以继续利用消息 ID 幂等语义。
- 落库与审计：`mt_comment_im_follow_up` 保存生成明文、来源、prompt/model/token/算力、`group_id`、`msg_id/cts`、阶段 attempt、状态、错误与耗时；管理后台“评价处理日志”对拥有 `comment:processing-log:retry` 权限的管理员提供三类失败任务的独立重试入口。
- 上线与逐步启用：参见 [差评 IM 跟进上线检查清单](./差评IM跟进上线检查清单.md)。

## 手动联调

### 查询门店 IM 状态

- 地址：`https://api-open-cater.meituan.com/wmoper/ng/im/getPoiIMStatus`
- SDK request：`com.meituan.sdk.model.wmoperNg.im.getPoiImStatus.GetPoiImStatusRequest`
- 本地入口：`backend/src/test/java/com/gogoga/backend/client/MtPoiImStatusClientManualTest.java`
- 执行保护：仅当 `MT_TEST_ENABLE_LIVE_API=true` 时真实调用美团接口。
- 必要环境变量：`MT_DEVELOPER_ID`、`MT_SIGN_KEY`、`MT_TEST_ACCESS_TOKEN`。
